Technical Evaluation of the Instatic Ecosystem: Architectural Profiles, Operational Mechanics, and Comparative AnalysisThe name "Instatic" refers to two completely separate software applications operating in different engineering and technology fields. The primary and actively developed application is Instatic CMS, an open-source, self-hosted visual website builder and Content Management System designed to generate and compile static, framework-free web assets. The secondary system is inSTATICS, a proprietary desktop structural analysis education tool built for the Microsoft Windows environment. This report provides an in-depth technical analysis of both platforms, detailing their origins, architectural designs, installation procedures across major operating systems, and core use cases, alongside a comparative analysis with market alternatives.Architectural Profiles and Origins of the Instatic Software SystemsThe two distinct software platforms named Instatic was each developed to solve specific problems in web development and structural engineering education.Instatic CMS: Market Genesis and Architectural MotivationInstatic CMS was created by CoreBunch, a bootstrapped software team featuring developers David Babinec and Rameez, who previously designed visual design tools such as Motion.page and the Core Framework design system. The creation of Instatic CMS was driven by both market conditions and technical goals.The Core Framework design token engine, although popular among WordPress professionals using builders like Bricks and Oxygen, experienced an 80% decline in revenue due to the rapid growth of AI-assisted coding tools and its positioning in a niche market. Rather than continuing to build plugins for existing platforms, the CoreBunch team pivoted to develop a standalone, unified visual publishing platform.From a technical perspective, the team wanted to solve the complexity of the modern headless web stack. Traditional decoupled static architectures require managing a headless CMS for content storage, a frontend framework like Next.js or Astro for rendering, an edge hosting provider like Vercel or Netlify for deployment, a separate form handler, and an image CDN. Instatic CMS collapses this entire stack into a single self-hosted Bun server.This visual website builder generates clean, semantic, and framework-free static pages. It was designed to compete with closed visual builders like Webflow—which locks user content into its platform and generates bloated, builder-specific markup—and legacy CMS monoliths like WordPress, which have a large security vulnerability surface and require ongoing plugin maintenance.┌────────────────────────────────────────────────────────┐

inSTATICS: Pedagogical Intent and Engineering BackgroundThe inSTATICS desktop application is an entirely separate software product developed by Halim K. Bas, PhD, PE, based in Florida, USA. Dr. Bas created inSTATICS as an interactive educational tool to address the complexity of professional structural analysis and finite element software.While industrial structural simulation suites require extensive configuration and training, inSTATICS provides a fast, visual platform for engineering students and university professors. It allows professors to quickly prepare exams and demonstrate structural behavior, and gives students an interactive solver to verify manual calculations of simple structures.Detailed Technical Architecture of Instatic CMSInstatic CMS is built on a high-performance, single-server architecture designed to balance designer control, developer flexibility, and system performance.The Unified Monolithic StackInstatic CMS runs on the Bun JavaScript runtime, utilizing Bun's native HTTP server, bundling, and file system APIs. The administration dashboard is built using React 19 with the React Compiler enabled and compiled with Vite.For data storage, the application defaults to an embedded SQLite database, storing all information locally within the application directory. For larger deployments, collaborative team workflows, or platforms requiring managed database backups, the application natively connects to a PostgreSQL instance via a connection string configuration.To provide extensibility without compromising server security, Instatic CMS runs a sandboxed plugin model. The server executes plugin backend code in isolated Bun.Worker threads that wrap a WebAssembly compilation of the QuickJS engine. This prevents custom plugins from directly accessing host resources, modifying the main process state, or crashing the core runtime.Plugins must request specific permissions (such as cms.routes to establish HTTP endpoints, or editor.code to run custom UI scripts in the admin pane) in a manifest file, allowing administrators to audit plugin code before activation.Style Isolation, Design Tokens, and the Unified Storage EngineInstatic CMS isolates styles at the component level to resolve class collisions and global stylesheet leaks. The engine automatically generates scoped class hashes for visual components, using a compiler to isolate styles:$$\text{Scoped Class Name} = \text{localName} + \text{"-"} + \text{MD5}(\text{resourcePath})[0..6]$$The visual editor integrates Core Framework, utilizing global design tokens for layout styling. Rather than generating inline overrides, visual configurations are compiled using variables that define the spacing, fluid typography, and color palettes. Changing a single token scale immediately updates the layout across all page components.For storage, Instatic CMS uses a unified data table architecture. Instead of separating system elements into custom databases, pages, blog posts, visual components, custom taxonomies, and form data are stored inside two central tables: data_tables and data_rows.Because form submissions are saved directly to these system-defined database structures, form submissions require no third-party APIs. The server dynamically reads the canvas form fields, generates matching database tables, and routes submissions locally.Atomic Static Compilation and DistributionThe static compiler compiles pages into flat, framework-free HTML and compressed CSS assets. When an editor publishes updates, the server pre-renders every page and writes it directly to disk. The server swaps active assets atomically, ensuring visitors do not encounter partially rendered pages during updates.For components that require dynamic processing, the engine detects interactive elements and injects a lightweight, vanilla client-side micro-runtime weighing approximately 1.1 kB. This micro-runtime processes dynamic components (such as shopping carts, page counts, or user login states) without requiring larger JS framework runtimes, resulting in fast initial loading speeds and optimal Core Web Vitals.The Canvas-Integrated AI Agent and Super ImportInstatic CMS includes an AI agent that modifies actual DOM nodes directly on the editing canvas, rather than outputting raw code snippets or mockups. Using a dual-scoped toolset (a 35-tool system builder and a 15-tool content editor), the AI generates structured semantic HTML and responsive CSS styles in real time.Because it uses a "Bring Your Own Key" system, developers can connect their own LLM APIs (such as Claude, OpenAI, OpenRouter, or a local Ollama instance running offline) to control API costs directly.For existing websites, the Super Import utility parses raw static files and reconstructs them on the visual canvas. Users can import an entire static site—including HTML, CSS styles, images, and custom typography. The engine automatically resolves style conflicts, maps elements to global design tokens, and parses media assets into the central file library, with a single-step undo history for safety.Operating and Deploying Instatic CMS Across EnvironmentsInstatic CMS can run in multiple environments, ranging from local offline developer systems to high-availability production cloud configurations.Deployment TargetPrimary DatabaseProcess ManagerExecution Command / ScriptPrimary StorageKey Use CasesLocal Workstation[cite: 13]SQLiteBun Runtimebun run dev[cite: 13]Local DiskRapid theme development, template design, layout experimentation.Self-Hosted VPS[cite: 13]SQLite / PostgreSQLDocker Enginedocker compose up -d[cite: 13]Mounted VolumeProduction-ready marketing landing pages, independent blogs, company portfolios.Railway Cloud[cite: 2, 15]SQLite / PostgreSQLPaaS Container RunnerOne-Click TemplateAttached Persistent VolumeManaged production environments, multi-author systems, fast SaaS deployments.Local Development Environment SetupTo initialize Instatic CMS in a local development context, the host system requires Bun (>=1.0) installed. The local environment uses SQLite for simple, dependency-free development.Bash# Clone the open-source repository
git clone https://github.com/corebunch/instatic.git
cd instatic

# Install all workspace dependencies
bun install

# Start the interactive local development server
bun run dev
By default, the Vite dev server launches on http://localhost:5173, allowing visual customization. To compile and launch the production build of the admin panel from the local Bun server, run:Bash# Compile client assets and launch on port 3001
bun run start
This serves the final application UI on http://localhost:3001/admin.Multi-OS Deployment via Docker and ContainerizationInstatic CMS is compiled into an official Docker image (ghcr.io/corebunch/instatic:latest), allowing it to run across Linux, macOS, and Windows Server. To run a secure, containerized production build with persistent data volume mapping, the environment requires several environment variables to structure system paths and enable core functions:DATABASE_URL: Set to a local file path (sqlite:/app/storage/data/cms.db) or an external database connection string (postgres://...).UPLOADS_DIR: Mapped to a persistent physical storage directory on the host to retain uploaded media assets across container restarts.STATIC_DIR: Directs the static compiler where to compile the generated HTML, CSS, and media bundles.INSTATIC_SECRET_KEY: A unique security key generated automatically at startup, used to encrypt LLM API keys and authenticate multi-factor authentication (MFA) logins.An optimized, production-ready docker-compose.yml file using a persistent storage volume and a SQLite database can be configured as follows:YAMLversion: '3.8'

services:
  instatic:
    image: ghcr.io/corebunch/instatic:latest
    container_name: instatic_core
    restart: unless-stopped
    ports:
      - "8080:8080"
    environment:
      - PORT=8080
      - DATABASE_URL=sqlite:/app/storage/data/cms.db
      - UPLOADS_DIR=/app/storage/uploads
      - STATIC_DIR=/app/dist
      - INSTATIC_SECRET_KEY=c39de98910ab3efcd9a9aefb839210c4  # Generate a cryptographically secure key
    volumes:
      - instatic_data:/app/storage
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:8080/health"]
      interval: 30s
      timeout: 10s
      retries: 3

volumes:
  instatic_data:
    driver: local
To run the containerized system in detached daemon mode, execute:Bashdocker compose up -d
Production Deployments via Cloud PaaS PlatformsFor cloud-based installations without server infrastructure management, operators can use one-click PaaS templates:Railway PaaS: Railway is the recommended hosting platform for Instatic CMS, provisioning the container runtime, attaching block volumes, generating randomized environment variables, and establishing secure SSL paths automatically. Single-site operators can use the SQLite template to limit compute overhead to approximately $5/month. For multi-author platforms, operators can use the PostgreSQL template to enable automated transactional backups.Render PaaS: Render hosts Instatic CMS by utilizing its native Docker container orchestration. They process plain-text markdown files and compile them into structured HTML using templating systems like Liquid or Nunjucks. While this approach offers excellent performance and security, it introduces a steep learning curve and lacks user-friendly interfaces for non-developer content creators.Decoupled headless frameworks (such as Astro or Next.js paired with systems like Strapi or Sanity) provide a visual content dashboard but require configuring a complex build pipeline. Any content update triggers an automated CI/CD redeploy on systems like Vercel or Netlify, which can delay updates on large sites.Instatic CMS resolves these trade-offs by combining a visual canvas editor directly with the static compiler. It compiles and writes updated static files directly to local disk storage instantly, bypassing external compilation pipelines or build queues. Non-technical users can edit the design visually while generating the optimized, lightweight output of a code-first framework.Technical Specifications and Evaluation of the inSTATICS Desktop AppThe inSTATICS Windows application is designed for structural engineering analysis and education, operating under completely different system parameters and scientific standards than Instatic CMS.Analytical Calculations and Mechanical ModelingThe core processing engine of inSTATICS evaluates structural systems (including trusses, continuous beams, and rigid frames) using matrix stiffness analysis. When structural geometries and loading vectors are applied to the visual matrix, the calculation solver models internal member behaviors by solving the differential equations of Euler-Bernoulli beam theory:$$EI \frac{d^4 w}{dx^4} = q(x)$$By integrating this equation across the boundary conditions of the joints, the solver calculates structural displacements:$$\mathbf{F} = \mathbf{K} \cdot \mathbf{U}$$where:$\mathbf{F}$ is the global node loading vector.$\mathbf{K}$ is the structural global stiffness matrix, compiled from individual elements.$\mathbf{U}$ is the vector of displacement components across structural nodes.This matrix solver calculates deformations and internal forces instantly as structural elements are moved or loading variables are modified, allowing students to observe cause-and-effect relationships in real time.Core Educational FeaturesThe program features specific utilities to assist structural engineering instruction:Visual Force and Displacement
